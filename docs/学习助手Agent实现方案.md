# 研数学习助手 Agent 实现方案

版本：v0.1（讨论稿）  
更新日期：2026-11-19  
适用范围：研数考研数学二助手

## 1. 目标与定位

研数不是给现有练习页面外挂一个通用聊天框，而是新增一个独立的学习助手页面，让 Agent 理解用户当前情况、查询已有学习数据、调用工具，并产出可执行的结果。

Agent 的职责是：

1. 理解用户的目标与约束。
2. 使用个人档案、偏好与历史信息判断当前最该做什么。
3. 通过工具读取错题、试卷、知识点与掌握情况。
4. 调用现有组卷、仿真与计划工具完成任务。
5. 用清晰的结果回复用户，并提供可继续操作的入口。

现有固定工作流继续负责可靠执行，Agent 负责决策与编排。不得让模型直接修改试卷、判卷结果或错题掌握数据。

## 2. 产品入口与交互

### 2.1 独立「学习助手」页面

在现有导航中新增「学习助手」，承载：

- 学习档案的首次填写与后续修改。
- Agent 对话与任务执行。
- 今日/本周学习建议。
- 计划列表与执行状态。
- 生成的试卷、仿真练习与复盘结果的入口。

页面不是营销页，也不是要求用户先写一段复杂提示词的空白聊天页。首次进入优先引导用户填写少量关键信息，例如届别、目标、当前基础和每周可用时间；已有档案时展示当前学习状态和建议。

### 2.2 用户动作示例

- 我今天有 1 小时，帮我安排一下。
- 我最近积分总错，帮我补一补。
- 把我最近的错题生成一张仿真卷。
- 帮我看看上次那张卷里哪些知识点还没掌握。
- 这周每天 30 分钟，给我一个能执行的计划。

Agent 应先利用已有数据给出具体建议；缺少必要条件时才追问，不为了“多轮对话”而反复询问。

### 2.3 需要用户确认的动作

- 涉及真实 AI 生成、消耗配额或耗时较长的任务。
- 创建或修改长期计划。
- 修改用户明确填写的档案字段。
- 任何可能改变学习记录的操作。

推荐交互是“Agent 提出方案 → 用户确认 → 调用工具 → 展示结果”，而不是自动替用户生成并打开一张卷。

### 2.4 交卷后的轻量入口

交卷结果页可以保留「诊断卡」：根据本次作答给出下一步建议，并跳转到学习助手页继续执行。诊断卡是助手的快捷入口，不替代独立 Agent。

诊断必须区分客观题和待复核解答题；待复核或数据不足时不得声称“用户不会”。

## 3. 用户信息与长期记忆

### 3.1 用户明确填写的档案（User Profile）

这是用户直接填写、修改的事实信息，例如：

- 考研届别、考试年份
- 目标分数/目标院校（可选）
- 考试科目：当前仅数学二
- 当前基础：薄弱 / 一般 / 扎实
- 当前阶段：基础 / 强化 / 冲刺
- 每周可用时间、每日可用时间（可选）
- 用户主动标注的薄弱知识点

规则：

- 只有用户明确填写或确认后才能修改。
- Agent 不得将推测写回该档案。
- 用户可在学习助手页查看、修改和清空。

### 3.2 Agent 自己总结的档案（Agent Summary）

这是 Agent 根据历史对话、工具结果和学习行为推断出的信息，例如：

- 最近关注的薄弱点及证据摘要。
- 最近已执行的计划与未完成任务。
- 用户对学习方式的反应。
- 需要下次验证的假设。

规则：

- 与 User Profile 分表/分字段存储。
- 可以自动更新，但保留更新时间和依据摘要。
- 标记为“Agent 推断”，不能包装成用户事实。
- 用户可以查看、修正或清除。
- 结论发生冲突时优先使用最新、证据更明确的记录。

### 3.3 用户偏好（Preferences）

单独存储，不混入事实档案：

- 偏好真题/AI/混合。
- 偏好的单次题量。
- 偏好的难度。
- 偏好简洁回复还是详细解释。
- 是否希望先给提示再显示完整答案。

偏好是偏好，不是学习事实；每轮对话注入。

### 3.4 会话摘要与记忆写入

长期记忆以结构化记录为主：

- 用户档案。
- Agent 总结。
- 用户偏好。
- 当前计划/目标 ID。
- 重要工具产物引用（试卷 ID、计划 ID）。
- 当前任务的已完成动作、未完成动作、待确认事项。

不把全部 501 道题、全部作答历史或整段原始对话当作长期记忆。详细内容通过工具按需读取。

## 4. 工具层设计

### 4.1 工具 Schema 规范

所有工具统一使用：

```json
{
  "name": "tool_name",
  "description": "何时调用、能做什么、不要调用的情况",
  "parameters": {
    "type": "object",
    "properties": {},
    "required": []
  }
}
```

参数使用 JSON Schema，明确必填项、枚举、长度与数量上限。工具返回结构保持稳定，包含：

```json
{
  "ok": true,
  "data": {},
  "summary": "供上下文使用的短摘要",
  "error": null
}
```

当前工具数量不多，工具 schema 全量注入，不额外做工具向量检索。未来工具数量显著增加时再按任务筛选，但不得提前引入复杂检索层。

### 4.2 首批工具范围

| 工具 | 用途 | 主要约束 |
| --- | --- | --- |
| `get_user_context` | 读取用户档案、偏好、Agent 总结和当前计划 | 只读当前设备 |
| `update_preferences` | 更新用户偏好 | 只写偏好，不能改用户事实档案 |
| `update_agent_summary` | 更新 Agent 总结 | 需记录依据与更新时间 |
| `list_wrong_questions` | 查询错题列表、掌握率和复习状态 | 默认摘要，支持筛选 |
| `get_question_detail` | 读取指定错题的题干、答案与解析 | 只读，按需调用 |
| `list_papers` | 查询用户历史试卷 | 只读，支持状态筛选 |
| `get_paper_detail` | 读取指定试卷、作答结果与题目 | 只读，长内容摘要 |
| `get_today_review` | 查询今日到期复习 | 只读 |
| `diagnose_attempts` | 按知识点聚合近期作答与失分 | 排除待复核题，注明样本量 |
| `compose_paper` | 创建真题/AI/混合组卷任务 | 复用现有校验和配额 |
| `create_wrong_variants` | 创建错题仿真任务 | 每题至少 3 道，复用现有限制 |
| `create_study_plan` | 生成并保存学习建议/计划 | 用户确认后写入 |
| `get_study_plan` | 查询计划及执行状态 | 只读 |

后续新增工具必须复用现有业务函数，不允许 Agent 直接执行任意 SQL、任意 HTTP 请求或任意代码。

### 4.3 执行与产物

- Agent 不直接代替现有 `generate.mjs` 的生成、格式校验、盲解自测和组装。
- 需要 AI 出卷或仿真时，创建现有 job 并返回任务 ID。
- Agent 可以轮询任务状态，但最终产物必须是实际存在的试卷或计划。
- 工具失败时返回结构化错误，不将失败包装成“已完成”。
- 多次调用同一动作必须带幂等键，避免重复扣额或重复建卷。

## 5. Agent 执行模型

### 5.1 推荐形态

采用：

> 固定执行框架 + 单 Agent 决策节点 + 工具循环

不做多 Agent 角色扮演，也不让模型在自由循环里无限探索。

一次用户任务的基本流程：

1. 读取用户上下文和当前任务。
2. 判断是否需要调用工具。
3. 选择工具并校验参数。
4. 执行工具，返回摘要和产物引用。
5. 根据结果决定是否需要下一步工具。
6. 输出最终回复，包含可执行入口。

### 5.2 循环边界

- 每轮工具数与总步数设上限，初版建议总步数不超过 6。
- 超过步数时返回部分结果与待确认事项，不继续无限运行。
- 模型输出不是合法工具参数时，允许一次修复重试；仍失败则降级为普通说明或现有手动路径。
- 所有工具调用必须在服务端执行并校验设备归属。
- 长时间出卷使用现有异步 job 和前端进度队列。

### 5.3 任务状态

Agent 任务至少包含：

```text
id
device_id
goal
status: queued / running / waiting_user / succeeded / failed / degraded
current_step
steps[]
context_state
created_at
updated_at
```

每个 step 记录：

```text
index
tool
arguments_summary
status
result_summary
artifact_ids
```

任务状态用于恢复与展示，不把完整工具返回体永久塞进对话上下文。

## 6. 上下文工程

### 6.1 每轮固定注入内容

每轮请求按稳定顺序组织：

1. 系统规则与角色边界。
2. 工具 schema（全量）。
3. 用户明确填写的档案（User Profile）。
4. Agent 自己总结的档案（Agent Summary）。
5. 用户偏好（Preferences）。
6. 当前计划与短期状态。
7. 会话摘要与保留的原始对话。
8. 当前用户输入。
9. 当前时间。

明确标注来源：

```text
用户明确填写的信息：事实，Agent 不得擅自改写
Agent 推断的信息：可能过时，必要时通过工具验证
用户偏好：偏好，不代表事实
```

当前时间放在上下文末尾，格式统一为：

```text
当前时间：YYYY-MM-DD HH:mm:ss（Asia/Shanghai）
当前日期：YYYY-MM-DD
星期：星期X
```

日期和星期由当前时间计算，不手写。时间在真正生成请求前格式化一次，不在同一请求的不同位置反复写入不同值。

### 6.2 上下文分层

| 层 | 内容 | 处理策略 |
| --- | --- | --- |
| L1 固定层 | 系统规则、工具 schema、档案、Agent 总结、偏好、当前计划 | 每轮注入，保持稳定以利缓存 |
| L2 保留层 | 原始对话与必要工具摘要 | 预算内原样保留 |
| L3 压缩层 | 最早、重复、已完成的对话片段 | 超预算时压缩为结构化摘要 |
| L4 按需层 | 试卷、错题详情、历史作答、完整解析 | 工具按需读取，不常驻 |

### 6.3 动态窗口预算

6w/8w 只是讨论时的例子，实际实现根据用户当前模型的能力动态计算。

模型配置至少记录：

```text
contextWindow
maxOutput
safeOutput
```

计算：

```text
inputBudget = contextWindow - safeOutput
```

输入预算再扣除：

- 固定规则与工具 schema 的实际 token 数。
- 档案、偏好、Agent 总结与计划状态。
- 当前用户输入。
- 本轮工具结果的预留空间。

剩余空间用于原始对话与压缩摘要。建议起始比例：

- 原始对话保留区：60%
- 会话摘要区：20%
- 当前输入、工具结果与短期状态：20%

具体比例按实测调整，不能超出 `inputBudget`。

### 6.4 保留与压缩策略

- 原始对话在保留区预算内原样保留。
- 接近上限时先生成候选摘要，再替换最早、重复度高的片段。
- 超过上限时压缩一批最早片段，保留最近完整任务。
- 不截断正在执行的工具调用、当前计划或待确认动作。
- 长列表、长试卷和长解析只保留引用与摘要，需要时再用工具读取。

压缩结果必须是可恢复状态，而不是泛泛散文，至少包括：

- 用户当前目标。
- 已完成动作。
- 未完成动作。
- 试卷/计划/错题等产物 ID。
- 已确认事实。
- 仍需用户确认的假设。

### 6.5 模型能力未知时

如果用户填写的模型不在已知配置表中：

- 不猜测其窗口能力。
- 使用保守的默认窗口与输出预算。
- 允许用户在模型设置中覆盖窗口参数。
- 在上下文统计或调试信息中标记“未知模型，使用保守预算”。

模型切换后重新计算预算，不沿用旧模型的分配。

### 6.6 Token 统计与缓存

- 使用对应模型的 tokenizer；没有时采用保守估算并记录误差。
- 请求前计算实际 token，不依赖字符串字数判断。
- 系统规则、工具 schema 和固定档案尽量保持前缀稳定。
- 时间放最后，减少其对前缀缓存的破坏。
- 记录输入 token、输出 token、压缩次数和截断原因，供调试与优化。

## 7. 与现有系统的集成

### 7.1 复用机制

必须复用：

- `providerFor` 与用户模型配置。
- 现有配额与超时机制。
- 请求幂等键与设备会话鉴权。
- 现有异步 job、阶段文案和右下角进度队列。
- 现有组卷、仿真、判卷与错题掌握率逻辑。

### 7.2 数据与隐私

- 所有学习数据按 `device_id` 隔离。
- Agent 只能访问当前设备的档案、错题、试卷与计划。
- 不把 API Key、原始 prompt、完整作答历史或模型内部错误暴露给前端。
- 长期记忆可查看、修改、删除。
- 计划与总结包含来源和更新时间。

### 7.3 失败与降级

- 未配置模型：提示「无法连接模型，请确认已配置模型」，可进入模型设置。
- 模型不可用：保留已有试卷、错题和计划查询能力，不伪造 AI 规划结果。
- 工具失败：显示真实失败原因和手动入口。
- 数据不足：说明样本不足，不生成虚假精确诊断。
- 待复核解答题：不能计入“已掌握/未掌握”的客观统计。

## 8. 最小 MVP 范围

第一版只做一条完整链路：

> 填写档案 → 用户提出目标 → Agent 调用工具 → 生成计划或练习卷 → 用户确认执行 → 查看结果

建议首批支持：

1. 学习助手页面与基础档案填写。
2. User Profile / Agent Summary / Preferences 的分离存储与注入。
3. 查询错题、历史试卷和今日复习。
4. 生成今日学习建议。
5. 调用现有组卷或错题仿真工具。
6. 将生成结果加入「我的试卷」。
7. 基础会话摘要与动态窗口预算。
8. 工具调用、计划与结果的展示。

暂缓：

- 多 Agent 协作。
- 向量数据库。
- 复杂账号体系。
- 自动删除错题。
- 自动修改用户事实档案。
- 生成精确到每天的长期承诺式计划。
- 全局聊天浮窗。

## 9. 验收指标与停止条件

### 9.1 功能验收

- 用户能填写档案并被后续对话正确引用。
- Agent 能读取当前设备的错题、试卷和复习状态。
- Agent 能创建真实练习任务，结果出现在「我的试卷」。
- Agent 的总结与用户事实档案明确分离。
- 模型配置、配额、幂等和异步进度均复用现有机制。
- 重启后档案、计划、试卷与 Agent 总结仍可恢复。
- 工具失败不会生成虚假的成功记录。

### 9.2 产品指标

优先观察：

- 学习助手首次使用后完成一次真实练习的比例。
- Agent 建议被用户确认并执行的比例。
- 计划或补练任务的完成率。
- 工具失败率、无效工具调用率和重复扣额次数。

不追求“聊了多少轮”，而看是否减少用户从问题到行动的步骤。

## 10. 实现顺序建议

1. 定义 User Profile / Agent Summary / Preferences / Study Plan 的数据结构与权限。
2. 封装首批只读工具和组卷、仿真工具。
3. 实现 Agent 的单任务执行器与步数上限。
4. 实现上下文构建、动态预算、摘要与时间注入。
5. 实现学习助手页面与确认交互。
6. 接入现有异步出卷队列和我的试卷。
7. 完成持久化、重启恢复、失败降级与契约测试。
8. 再做交卷后的诊断卡作为快捷入口。

核心原则：

> Agent 负责理解与选择，工具负责真实执行，长期记忆负责连续性，上下文工程负责可控成本。

## 11. 当前实现状态（2026-11-19）

已落地：

- `functions/agent-store.mjs`：用户档案、Agent Summary、偏好、计划、对话和任务的数据结构与区分。
- `functions/agent-tools.mjs`：工具 schema 全量白名单，覆盖用户上下文、错题、试卷、知识树、今日复习、诊断、组卷、错题仿真和学习计划。
- `functions/agent-context.mjs`：档案/推断/偏好注入、模型窗口动态预算、原始对话保留、摘要压缩、时间末尾注入。
- `functions/agent.mjs`：单 Agent 决策节点、工具循环、JSON 修复、确认握手和失败降级。
- `web/src/components/AgentPanel.tsx`：学习助手页面、档案/偏好、对话、工具步骤、任务历史、确认按钮和产物入口。
- Postgres/SQLite 持久化新增 `agent_states`，Agent 档案、偏好、总结、计划、对话和任务可跨重启恢复。
- `/api/agent/*` 路由已接入设备会话、provider、配额和现有组卷/仿真能力。

已验证：

- 契约测试 **16/16 通过**。
- 前端构建通过。
- 真实模型调用能执行 `list_knowledge_nodes → compose_paper`，生成试卷并返回真实 paper_id。
- 工具调用步骤、用户档案和 Agent 总结在界面中分别展示。
- Agent 等待用户确认后使用同一个 task 继续，不创建新任务。
- 未配置模型时显示「无法连接模型，请确认已配置模型」。
