## 数据样例

检查了 2005、2009、2021、2026 四份试卷，以及 2005–2026 共 22 份文件的命名和可打开性。

- 四份样卷均有文字层；每个 span 都有 bbox 和字体信息。
- 样卷 span 数分别为 1401、1411、1356、1482；PUA 字形数为 14、135、149、126。
- 字体包含 ArialUnicodeMS、CMEX10、CMMI 系列、CMR10，说明坐标和字体可用于重建公式，但不能靠线性文本直接恢复。
- 2005 年章节顺序为填空 → 选择 → 解答，2009/2021/2026 为选择 → 填空 → 解答。
- 2021/2026 的「解答题」标题有换行形态，切分需先做空白归一化。
- 2005/2009 有图形引用；图形应按题目 bbox 裁切，不做 OCR。
- 跨页题不能只靠正则按页切；应先在全卷建立章节和题号序列，再回溯每题的页面与坐标。
- 一个大题按一个题号保存，题号内的所有小问进入 `sub_items_json`，不把第二问拆成独立题。

建议实现顺序：

1. `extract_pdf.py`：输出 year/page/span/bbox/font/text，剔除页眉页脚。
2. `segment.py`：全卷空白归一化后建立章节与题号边界，处理跨页，生成 group/sub_items。
3. `normalize.py`：依据坐标/字体重建 LaTeX，保留原始 spans 和 hash。
4. 用 2005、2009、2021、2026 做固定样例，再批量跑 22 年。

## 平台适配

可复用：

- `function-backend/index.ts`：保留 Deno.serve、错误响应和平台 SDK 注入方式。
- `routes.mjs`：复用请求体上限、JSON 校验、路由后缀兼容、幂等创建和上传验证的结构。
- `dev/local.mjs`、`dev/proxy.ts`：参考本地内存依赖与 Vite 代理，但需要替换 notes 数据模型。
- `react-starter`：作为前端起点。
- `sse-chat`：只复用 SSE 解析、reader 清理和恢复模式，不部署其内存 service。

必须修改：

- 示例使用 `requireUser`；本项目无登录，改为服务端签发 device session，device_id 仅作匿名分桶，不能宣称安全身份。
- notes/attachments 路由替换为试卷、判卷、识别、复习、评测与举报路由。
- 管理导入、举报复核与匿名业务接口必须分开。
- 单一 `app` Function 内统一路由，不能部署多个业务函数。
- `contracts/schema.sql` 只使用允许的 DDL 和列类型，没有数组、numeric、CHECK、触发器或自定义函数。
- 发布预览不执行 Function，真实后端与模型必须在正式发布后验证。
